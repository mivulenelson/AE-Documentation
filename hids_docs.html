Autoencoder-HIDS Sentinel Console

A host-based network intrusion detection system powered by a symmetric autoencoder. Captures live packets, extracts 22 behavioral flow features, reconstructs them through a trained neural network, and flags anomalies when reconstruction error exceeds a calibrated threshold — all surfaced in a real-time PySide6 dashboard.

Python 3.12 PySide6 · Qt6 FastAPI · SQLite Keras · TensorFlow Docker Compose Scapy · psutil

01 — Overview

What it does

The HIDS Sentinel Console monitors network traffic on a chosen interface, extracts per-flow behavioral statistics, and runs them through a trained autoencoder to detect patterns that deviate from a learned baseline of normal activity. High reconstruction error = potential intrusion.

The system is split into two Docker containers: a FastAPI backend that handles live capture, model inference, and database persistence, and a PySide6 dashboard that renders alerts, charts, and forensic detail in real time over a shared SQLite volume.

⬡ Real-Time Detection

Live packet capture via Scapy. Flow features extracted per connection. Autoencoder inference on every captured flow with sub-second latency.

⬡ Forensic Inspection

Every alert persists to SQLite with full 22-feature breakdown, destination IP, protocol, encryption status, and analyst feedback fields.

⬡ Feedback Retraining

Analysts mark false positives directly in the dashboard. Accumulated flags feed a retraining pipeline that recalibrates the threshold automatically.

⬡ Compliance Reports

One-click generation of structured forensic reports covering threat summary, per-incident breakdown, and top anomalous flows — exportable as plain text.

02 — System Design

Architecture

The system follows a two-container architecture sharing data over Docker named volumes. The backend runs with NET_RAW and NET_ADMIN capabilities for raw socket access; the dashboard mounts the host X11 socket for GUI rendering.

Autoencoder Model

A symmetric feed-forward autoencoder with the following architecture. Trained on benign traffic; anomalies produce higher mean-squared reconstruction error (MSE). The detection threshold τ is derived from the training MSE distribution. 

# Architecture: 22 → 16 → 8 → 4 → 8 → 16 → 22
Input  (22)  →  Dense(16, relu)  →  Dense(8, relu)  →  Dense(4, relu)
                                                                ↓  bottleneck
Output (22)  ←  Dense(16, relu)  ←  Dense(8, relu)  ←  Dense(4, relu)

Threshold τ:  MSE_baseline + k·σ   (calibrated in configs/threshold.yaml)
Scaler:       StandardScaler saved as models/scaler.pkl
Weights:      models/baseline_ae.keras  v1.0.4

Data Pipeline

  • 1
    Packet Capture

    Scapy sniffs raw packets on the selected network interface with NET_RAW. Flows are grouped by 5-tuple: src_ip, dst_ip, src_port, dst_port, protocol.

  • 2
    Feature Extraction

    22 behavioral statistics are computed per flow — inter-arrival timing, packet length distribution, byte rates, burstiness, TTL diversity, and protocol flags. See Feature Vector.

  • 3
    Normalisation

    Features are scaled using the saved scaler.pkl (fitted on training data) before inference to match the training distribution.

  • 4
    Autoencoder Inference

    The 22-dimensional vector passes through the encoder→bottleneck→decoder. MSE between input and reconstruction is the anomaly score.

  • 5
    Alert Routing

    If MSE > τ, a new alert is written to SQLite and emitted as a Qt signal. The Sentinel Console updates in real time — no polling needed.

04 — Deployment

Docker setup

The project ships two Dockerfiles and a Compose file. All are built from python:3.12-slim. Runtime Python dependencies are loaded from the host virtualenv via a bind-mount (HOST_SITE_PACKAGES) rather than being re-installed in the image — this dramatically reduces rebuild time during development.

⚠

Root required. Both containers run as root for Scapy raw socket access. The cap_add: [NET_RAW, NET_ADMIN] entries are mandatory. The hids system user is created but not used for the running process — it exists so file ownership inside volumes is correct.

Dockerfile.backend

Installs libpcap, libgomp1, and curl (for the healthcheck). Copies api/, src/, and docker/entrypoint.py. Exposes port 9000. Starts Uvicorn via python -m entrypoint. 

# Healthcheck — backend is ready when /ready returns 200
HEALTHCHECK --interval=30s --timeout=10s --start-period=30s --retries=3 \
    CMD curl -sf http://localhost:9000/ready || exit 1

Dockerfile.dashboard

Installs the full X11/XCB/OpenGL dependency set for Qt6 rendering inside Docker, plus fonts-jetbrains-mono and libpcap-dev. Copies api/, src/, and the entire app/ directory. Starts with python app/dashboard.py.

ℹ

X11 forwarding. The dashboard container requires DISPLAY set to a reachable X server (default :0) and the /tmp/.X11-unix socket mounted. The launch script runs xhost +local:docker automatically. On headless servers, use a virtual framebuffer: Xvfb :99 & export DISPLAY=:99.

05 — Quickstart

Getting started

Prerequisites

OSLinux (Ubuntu 22.04+ recommended); X11 display for the dashboard
Docker20.10+ with Compose v2 plugin
Python3.12 — for venv + generate_threshold.py
Model filesmodels/baseline_ae.keras and models/scaler.pkl must exist before first launch
  • 1
    Create and activate the virtualenv
    python3.12 -m venv env
source env/bin/activate
pip install -r requirements.txt
  • 2
    Set HOST_SITE_PACKAGES in docker/.env
    # Find your venv site-packages path:
python3 -c "import site; print(site.getsitepackages()[0])"
# Paste the output into docker/.env:
HOST_SITE_PACKAGES=/path/to/env/lib/python3.12/site-packages
  • 3
    Place trained model files
    models/
├── baseline_ae.keras   # trained autoencoder weights
└── scaler.pkl          # fitted StandardScaler
  • 4
    Launch with run.sh
    chmod +x docker/run.sh
./docker/run.sh
# The script will:
#   1. Generate threshold.yaml if missing
#   2. Create docker/.env from .env.example
#   3. Load model files into Docker volumes
#   4. Run xhost +local:docker
#   5. docker-compose up --profile gui --build
  • 5
    Backend only (headless)
    cd docker && docker-compose --env-file .env --profile backend up --build
  • 6
    Development mode (live source mounts)
    cd docker && docker-compose --env-file .env --profile dev up --build

    Both containers mount the project root at /app — edits to src/ or app/ are live without rebuilding.

✓

Healthcheck. The dashboard container will not start until the backend responds 200 on GET /ready. If the backend is slow to start (first run with no model in the volume), increase start_period in docker-compose.yml or wait for the healthcheck to pass before the dashboard container launches.

06 — Reference

Feature vector (22 dimensions)

Features are extracted per TCP/UDP flow from captured packets and grouped into six semantic categories. The same 22-element order is used throughout: model input/output, the forensic inspector, the feature strip, and the per-feature error chart.
