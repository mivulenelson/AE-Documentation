What the system does

The system monitors network traffic on a selected network interface. It collects traffic information, extracts behavioral features from network flows, and uses a trained autoencoder model to identify activity that differs from normal traffic.

When the system identifies an unusual flow, the event is stored in the SQLite database and displayed in the Sentinel Console. The dashboard provides alert history, forensic information, model information, analyst feedback, and report generation.

Traffic is collected from the selected network interface.

Quick Start

The quickest way to start the project is by obtaining the repository files and using Docker. Before starting, ensure that the trained model files are available in the appropriate project directory.

Requirements

  • Ubuntu 22.04 or a newer Ubuntu release
  • Docker 20.10 or newer
  • Docker Compose version 2
  • An X11 display when using the graphical dashboard through Docker
  • The trained autoencoder model file
  • The trained scaler file
  • Git for obtaining the project repository

Repository Cloning

Clone the project repository and move into the project directory. 

git clone https://github.com/mivulenelson/autoencoder-based-HIDS.git
cd autoencoder-based-HIDS

Make sure you are inside the project directory before executing the Docker commands described below.

Docker Setup

Docker provides the recommended way to run the complete application. The project can be started using different Docker Compose profiles depending on whether you need the graphical console, backend service, or development environment.

Check Docker Installation

Verify that Docker and Docker Compose are available on your Ubuntu system. 

docker --version
docker compose version

GUI Mode

Start the graphical Sentinel Console together with the services defined under the GUI profile. 

docker compose --env-file docker.env --profile gui up --build

Backend Only

Start the backend without the graphical dashboard. 

docker compose --env-file docker.env --profile backend up --build

Development Mode

Start the development environment using the development profile. 

docker compose --env-file docker.env --profile dev up --build

Run in the Background

Add the detached option when you want the containers to continue running after the terminal is closed. 

docker compose --env-file docker.env --profile gui up --build -d

View Running Containers

docker compose ps

View Application Logs

docker compose logs -f

Stop the Application

Stop the running Docker Compose services with: 

docker compose down

Rebuild Without Cache

If changes to the Docker configuration or application dependencies require a clean rebuild, use: 

docker compose --env-file docker.env --profile gui build --no-cache

The commands above assume that the project contains a Docker Compose configuration with the profiles named gui, backend, and dev, and that the environment file is named docker.env. If the project uses different profile names or an alternative environment file, adjust the commands to match the project configuration.

Local Setup

Local execution is useful when developing or testing the project directly on Ubuntu without running the complete application through Docker.

Create the Virtual Environment

python3 -m venv env

Activate the Environment

source env/bin/activate

Install Project Requirements

pip install -r requirements.txt

Verify the Environment

python --version
pip --version

Model Files

Ensure that the trained autoencoder model and scaler files exist in the location expected by the application before starting the backend.

The exact local startup command depends on the application's Python entry point and project layout. Use the project's application entry point when starting the backend and dashboard locally.

Dashboard Components

Console Grid

Shows current alerts, previous alert information, summary metrics, threat rates, and a live signal chart displaying reconstruction error over time.

Packet Ingestion

Allows the analyst to select a network interface and observe system telemetry alongside collected network feature information.

Model Analysis

Displays model accuracy information, false positive information, current detection thresholds, and the retraining function.

Alert History

Allows the analyst to inspect stored alerts, feature values, reconstruction errors, destination addresses, and record analyst feedback.

Forensic Reports

Provides summary information about recorded events and generates structured text reports containing incident information.

Settings

Provides controls for the dashboard theme, network interface selection, and feature reference information.

Backend Endpoints

The backend API runs on port 9000. The following endpoints provide access to the main system functions.

Method Endpoint Purpose
GET /ready Checks whether the model is loaded and the database is accessible.
POST /capture/start Starts packet capture on the selected interface.
POST /capture/stop Stops packet capture and flushes the current flow buffer.
GET /alerts Returns stored alerts from the database.
POST /system/retrain Starts retraining using analyst flagged false positives.
